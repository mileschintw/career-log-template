# A Story is named within its section

The Story index keyed a Story by the entry section it links, `entries/<file>.md#<anchor>`, and `story-coverage` counted each key as one Story. But a Story is one point of an experience, and its facts often span several sections, while one section often holds several Stories: an experience's `## My contribution` can hold a library's origin and its launch, or three separate events. So an interview plan could print several `story carries too many questions in one interview` lines of which only one was a real double use, the others different Stories in one section; the agent explained those away by hand, and the interview mode's Done when could not be met honestly. The cue card and the question-to-Story finder (#706) need one row per Story, which needs a name the tools can read.

So a Story may carry a name within its section. In `stories.md` the name is the link's title, `[<label>](entries/<file>.md#<anchor> "<name>")`, a slug, so the link still resolves to its section and the label stays free text; in tool input and output the key is `entries/<file>.md#<anchor>~<name>`. The name is optional: a key without one keeps its old meaning, the whole section as one Story, so `#sec`, `#sec~a` and `#sec~b` are three keys and no Log has to change. Every reader of a key takes the named form (the Story index, a Talking points file's `## Stories`, an interview pack's `Lead:` line, `story-coverage`, `story-candidates`, `story-leads`, `story-finish`); `story-add --story` writes a name and `story-name` adds one to an item already indexed. The two too-many findings end with a hint to name the Stories when the key has none, and the stories mode then proposes names from each row's label and summary for the user to accept. The upgrade offers the same: one `review:` line per unnamed key listed in two or more rows.

We considered a `--distinct <key>` flag on `story-coverage` that the user's yes would allow for one run, with no format change: it silences the line once and names nothing, so the next run and the finder are back where they started. We considered one Story per section, enforced by consolidate: it contradicts "a long experience holds many Stories" and splits an experience's sections by interview use rather than by what happened. The cost of a name: the title must be repeated in a Talking points link for its lead to keep the same key, and a name the user never gives leaves a shared section counted as one Story, as before.
