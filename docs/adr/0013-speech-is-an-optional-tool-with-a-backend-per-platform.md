# Speech is an optional tool with its own environment and a backend per platform

Spoken practice needs the agent to hear the user, and only a transcript with times lets it time a talk, find its pauses and part lengths, and check a told Story against the Log. Built by hand in session scratch folders, that transcription was rebuilt again and again, ran on the CPU on a GPU machine, and kept the words a model invents from trailing silence. So the Engine takes `tools/speech.py` (#707), as an optional tool of Machine setup ([ADR 0007](0007-direction-config-and-machine-setup.md)): the first one with models to download and a different backend per platform. This extends ADR 0007's rules for optional tools:

- **Its own environment.** `tools/speech.py` uses the standard library only and is run like every other tool. Its setup creates `~/.career-log/speech/venv`, installs the packages of `tools/speech-requirements.txt` there (the backends, PyAV and the NVIDIA libraries pinned to one version), and downloads the models into `~/.career-log/speech/models`; `transcribe` re-runs the script with that environment's Python. Removing the folder removes all of it, nothing needs an administrator, and no system package (FFmpeg, CUDA) is required: PyAV's wheels bundle FFmpeg, and NVIDIA's cuBLAS and cuDNN come as wheels, installed only when an NVIDIA GPU is found.
- **A backend per platform, one shared layer.** A backend turns audio into words with their times: faster-whisper (CTranslate2) on Windows, Linux and x86-64 Macs, on the GPU when one is usable and else on the CPU, tuned; mlx-whisper on Apple Silicon. Both are Whisper models, because a prompt of proper nouns (`--terms`) and a second, smaller model (`--check`) need one. Everything printed (duration, words, pace, pauses, part timings, the words the two models heard differently, the text dropped after the last speech) is computed from those words by plain Python, the same on every platform and tested in CI from a JSON fixture. Changing a backend touches one place.
- **The offer names the alternatives.** The Trigger check offers the tool the first time a mode takes a spoken answer, with what each way gives: `speech.py` (recommended: times, so pace, pauses and part timings), the agent app's own voice input (a transcript only), or typing. The answer goes in `machine.toml` like any optional tool's; after a no the check does not ask again and a round uses one of the other two. Setup's quick round does not ask about it.
- **Every run says what ran it.** Each run prints the device and its speed in times real time; slower than 3x, it names a faster option this machine has, if any. Measured speeds are kept in the pull request, since the backends are tested once per machine by the maintainer ([ADR 0006](0006-engine-testing-works-in-phases.md)), not in CI.

Recordings stay outside git (`.gitignore` ignores audio files) and are never uploaded; the transcript goes to stdout, and the practice log keeps what the round needs.

## Considered options

- **One backend everywhere: a Parakeet model on ONNX.** The fastest on a CPU and one code path for all platforms, but English only and with no prompt of terms, which the proper nouns of a technical talk need.
- **CTranslate2's Metal backend on Apple Silicon**, making faster-whisper the only backend: newly released and experimental, with no published Whisper figures. It may replace mlx-whisper later; the shared layer does not change when it does.
- **Install through the setup scripts**, like playwright-cli: `tools/setup.sh` and `setup.ps1` would each need the backend choice, the GPU detection and the model download twice over, in two shells. `speech.py setup` does it once, in Python, and records the answer in `machine.toml` the same way.
- **Leave it to the agent app's voice input**: nothing to install, but no times, so no pauses, pace or part timings, and dictation may tidy away the slips a practice round is for. It stays as the offer's second way.
