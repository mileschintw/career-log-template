# Mode: import

Before anything else in this mode, run the **Start check** in [SKILL.md](../SKILL.md), once per session.

Bring old resumes, CVs, LinkedIn exports, bios or reports into the log. Different versions describe the same experience in different words and contexts; the job is to merge them into one entry per experience without inventing anything. The originals stay unchanged in `sources/`, so nothing is lost when an entry keeps each wording only once.

When the source is an AI chat history (a ChatGPT, Claude.ai or Gemini export, or Perplexity), follow [import-chats.md](import-chats.md) instead of steps 1–2: the raw export stays out of git and only the conversations the user picks are copied. When it is another logged-in website (a LinkedIn profile), first follow [import-web.md](import-web.md) to capture it into `sources/<origin>/`, then continue from step 3 with those files.

1. **Collect and preserve the originals.** Take every file in `sources/inbox/` (or the files the user handed over, copied there first). Move each, unchanged, to `sources/resumes/<YYYY-MM-DD>-<label>.<ext>` (the document's date when it gives a day, otherwise the import date, with the document's own date noted in the report) if it is a resume or CV, otherwise to `sources/<origin>/` (e.g. `linkedin/`) with the same naming. Ask the user for a document's date or target role only when the file and its name do not show it.
2. **Extract text.** `.md`/`.txt`/`.tex`: read directly. `.docx`/`.rtf`/`.doc`: `textutil -convert txt -stdout <file>` on macOS, `pandoc -t plain <file>` elsewhere. `.pdf`: the Read tool. Check each extraction is complete before moving on.
3. **Split into items.** For each document list every experience item (job, internship, project, research, leadership, award, course), plus profile facts (contact, education, skills, languages).
4. **Match items across documents and against existing entries.** Same organisation and overlapping period is a match; for projects, the same project under a different title or framing is a match too. Classify each item as **match**, **new**, or **ambiguous**. Put every ambiguous case to the user in one numbered round with your proposed answer, and wait. Ask in the same round for any new item's start month when no document gives one; without an answer, name the file by the document's month and write `period: GAP – YYYY-MM` (or `GAP – GAP` when the end is unknown too).
5. **Merge into entries.** For each experience:
   - Create the entry from `entries/_template.md` if it is new, and add it to `README.md` with status `imported`. Keep its `visibility: GAP` unless a document settles it (a personal project in a public repo: `public`, cited by the repo; work the document calls confidential or under NDA: `nda`, cited by the document) or the user says which during the import; a value other than `GAP` replaces the template's comment with its source (`visibility: public  # (<repo URL>)`, `# (user, YYYY-MM-DD)`).
   - Add each distinct bullet, verbatim, under `## Past phrasings` with its angle (the resume target it suits, as `entries/_template.md` defines it) and its source file. A bullet repeated across versions, word for word or nearly, goes in once, citing the newest version. Consolidate trims the section to two per angle.
   - Lift facts (dates, titles, numbers, technologies, outcomes) into the matching sections, each with provenance `(sources/resumes/<file>)`.
   - Record contradictions between versions (different dates, numbers, titles, scope) under `## Conflicts`, as a line starting `Open:` that quotes each side with its source. Leave them unresolved for consolidate, unless the user rules on one during the import (then settle it as consolidate step 2 says).
   - Leave every section the documents cannot fill as `GAP:`.
   Merge profile facts into `profile.md` the same way.
   Then deny the names of each entry file this step created or changed, as *Names appended to `.export-deny`* in [SKILL.md › Commits](../SKILL.md#rules-for-every-mode) says.
   A value for a Direction item or a Config field (`python3 -I <root>/tools/config.py fields` lists them: a resume's objective naming a target role, a visa, citizenship or "no sponsorship required", a sorting order, a record language) goes only into the import report, under *Found for setup*, with its source: `direction.md`'s items and `config.toml` change through setup alone. Step 7 offers each one.
   For any story an imported item could tell (a hard bug, a lead role, a conflict), add a link under its question type in `stories.md`, marked *(raw)*.
6. **Write the import report** as a new section in `sources/import-log.md`: files imported; entries created and updated; conflicts found; *Found for setup* (step 5); and, per entry, how many `GAP:` markers it has and which entry to consolidate first. The gaps themselves stay in the entries, where answering one removes it. A fact or ruling the user gives during the import goes into its entry with `(user, YYYY-MM-DD)`, never only into this report.
7. **Show the report**, then commit as *Bulk data changes* in [SKILL.md › Commits](../SKILL.md#rules-for-every-mode) says: `import: <n> file(s), <m> entr(y/ies)`. Then offer each *Found for setup* value, one at a time, through [setup › Changes](setup.md#changes).

Done when every file in the inbox is preserved under `sources/resumes/`, every item from every document is either in an entry or listed in the report as deliberately skipped (with the reason), and every conflict is recorded; the user has answered the import: yes (committed and pushed) or no (undone); and each *Found for setup* value has been offered.
