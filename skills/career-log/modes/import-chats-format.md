# Chat export format changes

Read this when a platform's export no longer parses: [import-chats.md](import-chats.md) step 2 sends you to *Format notes* to fix the parser, and step 8 to *Report upstream* once the import is done.

## Report upstream

Only when [import-chats.md](import-chats.md) step 2 or another step needed a fix or a workaround, and only after the import is done:
1. Tell the user what broke (which platform, which file, what the parser expected and what it found) and what you changed.
2. Offer to send it to the Template's upstream repo, https://github.com/mileschintw/career-log-template, named in the Template `README.md` under *Upstream*.
3. Draft the report. It describes the change with a redacted structural sample: keys, types and nesting only, with no message text, names, ids, dates or URLs. Nothing in it may come from the user's Log. For a pull request on ChatGPT, Claude.ai or Gemini Apps, the sample can be a fixture: `python3 -I tools/tests/make_fixtures.py`, with one of `--chatgpt <export .zip or folder>`, `--claude <conversations.json, its .zip or its folder>` or `--gemini-apps <the Takeout folder>`, plus `--out <scratch>/fx`, keeps the structure, replaces every text with made-up words, and writes nothing unless its checks pass. A Perplexity capture or a Gemini in Workspace export has no fixture builder yet: describe its structure by hand. Show the user the fixture's diff with the rest of the draft. For a pull request, rebuild that platform's fixture in place too (the same command with `--madeup --out tools/tests/fixtures`, so the made-up cases the tests need stay; the other platforms' fixtures stay as they are), run the tests with `--update`, and include `tools/tests/` in the patch below.
4. Post nothing until the user says yes to that specific draft. Then send it one of two ways:
   - **Issue** (public, so anyone can read it): show the user the full body first. It follows the repo's "Chat export format changed" form: platform, what broke, the redacted sample, the parser change, the Template version (the commit in `tools/TEMPLATE_VERSION`; when that file is missing, the date of the repo's first commit, `git -C <root> log --reverse --format=%cs`'s first line, which upstream matches to the publish before it). Then `gh issue create -R mileschintw/career-log-template --title "<platform>: <what changed>" --label chat-export --body-file <scratch>/issue.md` (`--body-file` skips the form and its label). GitHub keeps the label only when the sender has push access to upstream, and drops it silently otherwise; the maintainer labels the issue then. If gh answers that the label is not found, run it again without `--label`.
   - **Pull request:** a repo made with "Use this template" shares no git history with upstream, so it cannot open a PR from itself. Send only the user's own change, never whole files: their copy of the Engine may be older than upstream, and a copied file would undo upstream's later work. Make the patch against the commit the repo was created from (its first commit, `git -C <root> rev-list --max-parents=0 HEAD`): `git -C <root> diff --output=<scratch>/fix.patch <first commit> -- tools/ skills/` (`tools/` includes `tools/tests/`) (`--output`, not `>`: Windows PowerShell 5.1 writes redirected output as UTF-16, which `git apply` rejects), then cut every hunk that isn't this fix. Fork and clone upstream into the scratch space (`gh repo fork mileschintw/career-log-template --clone`), then in that clone `git switch -c fix/<platform>-format` and `git apply --3way <scratch>/fix.patch`; if it does not apply cleanly, show the user the conflict and offer the issue instead. Run the tests there, check the diff holds nothing from the Log, commit, `git push -u origin HEAD`, and `gh pr create -R mileschintw/career-log-template --head <user>:fix/<platform>-format --title "<platform>: <what changed>" --body-file <scratch>/issue.md`.

## Format notes

After any change to `tools/chat_export.py`, run its tests, the check [SETUP.md](../../../SETUP.md) step 7 lists for it. They index the anonymised fixtures in `tools/tests/fixtures/` (one sample per platform, built from real exports by `tools/tests/make_fixtures.py`, with every text replaced by made-up words, every key outside the platforms' schemas renamed, and every time made up; two independent checks, one against the source export itself, must pass before anything is written), repack them every way [import-chats.md](import-chats.md) step 1 allows, and compare the results with `tools/tests/expected/`. A change in behaviour that is meant shows up as a failing comparison: rerun with `--update`, read the diff of `expected/`, and commit it with the change. A new export format gets its own fixture the same way: rebuild the platforms that have it, `python3 -I tools/tests/make_fixtures.py --chatgpt <export .zip or folder> --claude <conversations.json, its .zip or its folder> --gemini-apps <Takeout folder> --madeup --out tools/tests/fixtures` (any of the three; a platform left out keeps its current fixture), then `--update` and review both diffs. The builder replaces the folder only when both its checks pass, and lists any value or key it had to replace that a new format may need kept; add one to `KNOWN_ENUMS` or `SCHEMA_KEYS` only after looking at it.

What the parser handles, for fixing it when a platform changes its format:
- **ChatGPT:** each conversation is a tree (`mapping`). The visible thread is `current_node` followed up through `parent`. User messages on other branches are edited prompts, kept as `T<n>.A<k>` because the first wording is sometimes the more honest one. Skip messages marked `is_visually_hidden_from_conversation` (system and tool scaffolding).
- **Claude.ai:** `chat_messages[]`, `sender` `human` or `assistant`. Pasted files are in `attachments[].extracted_content` and are kept. Uploaded files (`files[]`) are not in the export.
- **Gemini Apps:** an activity log, not conversations. Each `outer-cell` div is one prompt with its answer. The timestamp is localised (for example `Mar 5, 2026, 2:01:00 PM PST`, or the Chinese form with a period word such as 清晨 or 下午 before the hour; `ZH_AM`/`ZH_PM` list them). A record with an unknown form is skipped with a warning, so add the form rather than ignore the warning. Only "Prompted" records and "Branched" ones (a prompt asked again on a new branch) become user turns. A Canvas Gemini wrote ("Created Gemini Canvas titled …") becomes an assistant turn, since its body is AI text, and bookkeeping records ("Used Gemini Apps", feedback) are dropped with a count. Time-zone names map to UTC through `TZ_HOURS`; an unknown name is read as UTC with a warning. The Gemini Apps folder name is localised too: `GEMINI_FOLDERS` lists the known names, and a My Activity page in an unknown folder is skipped with a warning, so add the name. The parser skips uploads by their `-<16 hex>` suffix, merges records from every Takeout given (each counts once by its time and its prompt or Canvas title, with the most recent Takeout's non-empty answer), and groups prompts into sessions at gaps over 45 minutes (`--gap`, at least 1). Some answers are missing or empty in the export, and attachments appear only as file names.
- **Perplexity:** the capture JSON is `[{slug, title, space, entries: [{t, q, a, att}]}]`, written by the recipe in [import-web.md](import-web.md).
