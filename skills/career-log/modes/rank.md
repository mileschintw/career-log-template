# Mode: rank

Sort a list of employers (a career fair roster, a job board export, a set of postings) into tiers the user can act on, and give each worthwhile one an opening line backed by the log.

1. **Load the rules.** Read `direction.md` in full: the role ranking, the sorting order under Employer preferences, the Constraints, and What to emphasise, by target. When work authorisation is unanswered, ask the user whether any employer is ruled out by it (a visa they need sponsored, a citizenship or clearance they lack), at the point of need ([SKILL.md › Settings](../SKILL.md#settings)): it decides what step 2 researches. When the target roles are unanswered, ask for them the same way: step 2 looks for teams in those areas and step 3 measures domain fit against them. When they are skipped or the user declines, use the areas the entries' tags show most instead, and say so in the report. Read `applications.md` for earlier contact with any listed employer.
2. **Research each employer.** For every name on the list, look up from the web, citing each fact's URL:
   - what it builds, and which teams hire engineers in the user's target areas;
   - each hard constraint `direction.md › Constraints` answers: whether the employer meets it (for a visa the user needs, whether it sponsors that visa; US H-1B filing history, for example, is public data; for a location, where the roles are). A skipped or unanswered constraint is not researched. Whatever Constraints says, note whether its roles need citizenship or export-control clearance;
   - size and stage.
   Mark anything not found as `GAP:`. Research in parallel with subagents when your agent has them and the list is long, otherwise one employer after another.
3. **Score in the order `direction.md` gives.** Hard constraints first, as a gate: an employer that breaks one in `direction.md › Constraints` (it will not sponsor the visa the user needs, its roles need a citizenship or clearance the user lacks) is out, whatever else it offers. An employer whose roles need a citizenship or clearance that the work authorisation answer does not mention is not out: list the requirement in its row as something to check. Then the sorting order under `direction.md › Employer preferences`. When it is unanswered, ask the user for it before scoring, at the point of need ([SKILL.md › Settings](../SKILL.md#settings)), proposing domain fit against `direction.md › Target roles, ranked` (or the entries' areas, as step 1 says), then size and pay. When it is skipped or the user declines, score in that proposed order and say so in the report.
4. **Write the tiers.** For each employer: tier, one-line reason, the evidence for each hard constraint, and for the top tiers an opening line that names the entry to lead with (from `direction.md › What to emphasise`) and one question to ask them. Every claim about the user traces to an entry.
5. **Show the ranking** to the user and apply their changes. Their reactions to companies are direction: record them in `direction.md`.
6. **Save** to `outputs/reports/<YYYY-MM-DD>-<event>-ranking.md` with the sources, add the event to `applications.md › Events and contacts`, commit and push: `rank(<event>): <n> employers`.

Done when every employer on the list has a tier with evidence for each hard constraint or an explicit `GAP:`, every top-tier employer has an opening line traced to an entry, and the event is in `applications.md`.
