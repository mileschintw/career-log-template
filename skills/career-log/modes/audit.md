# Mode: audit

Before this mode's first step, run the **Trigger check** in [SKILL.md](../SKILL.md).

Report how ready the log is to produce outputs. Read-only: its only writes are the target builds under `.build/` (point 6's `--stale`). Everything else, `outputs/` included, it only reads, and its result is the report it prints.

Run `python3 -I <root>/tools/entries.py check --root <root>` once and report each finding it prints under the point below that names its kind (point 7 for a kind no point names); point 5 judges its `check:` lines. `python3 -I <root>/tools/entries.py --help` says what each kind means. Then check and report, most important first:

1. **Story coverage.** The findings of `python3 -I <root>/tools/entries.py story-coverage --root <root>`, the same report the [stories](stories.md) mode starts with, then each question type whose only entries are thin.
2. **Gaps.** The `state:`, `key section empty:` and `blocking gaps:` lines of `python3 -I <root>/tools/entries.py state --root <root>`, run once (it reads every entry).
3. **Provenance.** The check's `results row missing`, `source key unresolved` and `source folder not in keys.md` lines; then numbers outside the Results tables missing a source, measurement or caveat.
4. **Conflicts.** The `Open:` lines of the entries' and `profile.md`'s Conflicts sections, and the check's `conflict line not Open or Settled` and `settled line not in a template form` lines.
5. **History in the files modes read** ([SKILL.md › Current truth only](../SKILL.md#rules-for-every-mode)):
   - **`## Past phrasings`:** the check's `past phrasing` lines; a citation that holds anything but the source (a usage note, such as the company or posting the wording was sent to), where a wording from an output cites the form `write` prescribes (an application folder's path, `outputs/resumes/<target>.tex, YYYY-MM-DD`, or a bullets report's `outputs/reports/<YYYY-MM-DD>-<slug>.md`); and, in `consolidated` entries, more than two wordings of one claim for one angle.
   - **Every file modes read:** the check's `check: output citation:` and `check: record note:` lines, each judged (an earlier design or replaced component of the project itself is a fact, not a note about the record); then any other fact that cites an output without its path, and any other note about the record in other words.
   - **`direction.md`:** replaced answers kept beside the current one, and event stories instead of the rule they teach (the sourced "why this path" account is neither).
   - **`stories.md › Application questions`:** the `application question:` lines of `python3 -I <root>/tools/entries.py story-coverage --application-questions --root <root>`.
6. **Outputs.** `applications.md` events with no next step; each `finding:` line of `python3 -I <root>/tools/check_save.py --audit --root <root>` (the outputs' layout, missing provenance tables and provenance rows); when `outputs/resumes/` holds a `.tex`, each `FAIL:` line of `python3 -I <root>/tools/resume.py --stale <root>/outputs/resumes --root <root>` (audit installs nothing: when it exits 2, TinyTeX or poppler is missing or failed, so report that the compare did not finish, with its last lines and any `FAIL:` line above them): `is not the one its .tex builds` is a target whose committed `.pdf` was built from something else, so a sent-version hash would point at the wrong PDF; `does not build` is a broken `.tex`; `this machine lacks <file>` is a LaTeX package missing on this machine, not a fault of the resume, so report that this target was not compared and give the user the command after `was not compared:` (it installs the package and builds the copy under `.build/audit/`), then the `--stale` line above to run again; when that command prints `tlmgr found no package providing <file>`, either the `.tex` names a package no TeX has (a broken `.tex`) or tlmgr could not reach its repository, so say both and let the user check which; and `no <target>.pdf` is a target never built. Each is reported with its target. Then check the saved text of the outputs against the entries' current rulings, as *How to check outputs* says. Report each output an employer may still read that uses a wrong side, a do-not-use claim or a context form's wording outside its context, with its file and line. A `## Risks to handle in conversation` section is not a finding: it names those claims on purpose, as warnings. A hit in a target or an unsent folder is fixed before it is sent; a folder is frozen once sent, so a hit there is reported as a risk to handle in conversation, never as an edit (ask the user which folders were sent when nothing in the log says).
7. **Staleness and format.** The check's findings no point above names (consolidate first the entries with `pending` lines); then each `README.md` row's status and status note against its entry's body.

End with a short ranked to-do list (which entry to consolidate first and why). Fixing more than one entry from that list is a bulk change ([commits.md › Bulk data changes](../commits.md#bulk-data-changes)). Then run the command [SKILL.md › Next up](../SKILL.md#rules-for-every-mode) gives, with `audit`.

Done when every entry in `README.md` has been checked against all seven points: every entry, every point, never a sample. Required reads: each entry file in full, frontmatter included (read the whole file, not its first lines or a grep), `README.md`, `stories.md`, `profile.md`, `direction.md`, and the outputs point 6 and *How to check outputs* name. The last message ends with the Next up block.

## How to check outputs

- **An application folder** (point 6): leave it unbuilt: a build copies the PDF next to the `.tex` (`tools/resume.py`), over the folder's `resume.pdf`, which in a sent folder is the one the employer received.
- **Saved text against current rulings** (point 6): run `python3 -I <root>/tools/entries.py rulings-hits --root <root>` (`--help` gives its lines) and judge every line it prints. For each `check:` line, read the output for the ruling's claim, whatever its hits: a `hit wrong` or `hit do-not-use` is a point-6 finding, a `hit context` is one where the output uses it outside its context, a `hit right` is none, and the claim in other words counts as the wording would. Read the output a `no provenance:` or `unreadable:` line names against every `ruling:` line, and the row an `unresolved:` line names against the entry it means. Done when every line has a verdict.
