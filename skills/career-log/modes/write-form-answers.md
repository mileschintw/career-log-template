# write: form answers

How [write.md](write.md) step 5 finds each form question's row and picks its answer's starting point, one question at a time. A step named here by its number alone is write.md's; the numbered items below are the paths.

Find the question's row in `stories.md › Application questions`: `python3 -I <root>/tools/entries.py answer-row "<question type>" --angle <angle> --root <root>` prints its scope and pointers, or `no row:` and the row types. A question no row on the `row types:` line covers is a new question type: propose a row and a scope (`per-angle` when unsure: a `shared` answer that should have differed per role is the costlier mistake), and once the user confirms both, run `python3 -I <root>/tools/entries.py answer-row-add "<question type>" --scope <scope> --root <root>` before drafting. The angle is this run's resume target, as `entries/_template.md › Past phrasings` defines it: in a target run, its own target, named now as step 6 says for `<target>` (reuse a name `application.py start` lists), the name steps 6 and 10 then use ("a general backend engineer resume" takes the backend target, not `general`); in a posting run, the target in `outputs/resumes/` closest to its role, or `general` when none fits or there are none yet. Start from the first that exists:
1. in a posting run, this company's earlier answer to the same question type (a target run starts at 2): `python3 -I <root>/tools/application.py prior "<company>"... --type "<question type>" --root <root>`, with step 3's names. The candidate is its first `answer:` line, else the first `untyped:` line (a folder saved before `Type:` lines) whose heading matches the row. A `sent before:` line is an Archived folder's answer (or, untyped, a heading to match), never a starting point ([write.md › Save levels](write.md#save-levels)): it goes under step 9's **Sent to this company before** heading, for the user to compare, and the draft takes none of its wording. With no candidate, go on to 2;
2. the file at the path on the first `pointer:` line `answer-row` printed, unless that line starts `pointer: none`;
3. the row's material and the user's direction for it, plus, for a `per-company` row, research on the company: step 2's company lookup, and what else the question needs (cite each fact's URL). Join the lookup before choosing a `per-company` answer's starting point; the rest of step 5 does not wait for it. A `per-company` question in a target run has no company: ask for one, or draft from the material and direction alone and say so.

A match from 1 or 2 is a candidate, not a default: answers age (a "recent technology" answer goes stale in months, and a change of direction changes even shared answers). Show it with its date (the folder's or report's date) and what changed since: newer entries and changes to the files the answer draws on (for a path 1 candidate, the `since <date>:` lines `prior` printed; for a path 2 file, `git -C <root> log --since=<date> --oneline -- entries/ direction.md stories.md profile.md`), and a different target or company. Recommend one of three, and let the user pick before drafting: **reuse** it as is (it still goes through step 7 and the review), **adapt** it (step 6 edits it), or **rewrite** it from the row's material.

Done when every free-text question has its row and scope (a new row confirmed by the user) and a starting point: a candidate from path 1 or 2 the user chose to reuse, adapt or rewrite, or path 3's material.
