# write: form answers

How [write.md](write.md) step 5 picks each form answer's starting point, one question at a time. A step named here by its number alone is write.md's; the numbered items below are the paths.

Find the question's row in `stories.md › Application questions` and its scope there (`shared`, `per-angle` or `per-company`). A question no row covers is a new question type: propose a row and a scope (`per-angle` when unsure: a `shared` answer that should have differed per role is the costlier mistake), and ask the user to confirm both before drafting. The angle is this run's resume target, as `entries/_template.md › Past phrasings` defines it: in a posting run, the target in `outputs/resumes/` closest to its role, or `general` when none fits or there are none yet. Start from the first that exists:
1. this company's earlier answer to the same question type, from step 3's folder search: the question whose `Type:` line names the row, or, in a folder saved before `Type:` lines, the question whose heading matches the row. A folder holding `archived.md` is not a starting point ([write.md › Save levels](write.md#save-levels)): its answer goes under step 9's **Sent to this company before** heading, for the user to compare, and the draft takes none of its wording; the search goes on to the next folder, then to 2;
2. for a `per-angle` row, its pointer for this angle, then its `general` pointer; for a `shared` row, its one pointer. A `per-company` row has no pointer;
3. the row's material and the user's direction for it, plus, for a `per-company` row, research on the company: step 2's company lookup, and what else the question needs (cite each fact's URL). Join the lookup before choosing a `per-company` answer's starting point; the rest of step 5 does not wait for it. A `per-company` question in a target run has no company: ask for one, or draft from the material and direction alone and say so.

A match from 1 or 2 is a candidate, not a default: answers age (a "recent technology" answer goes stale in months, and a change of direction changes even shared answers). Show it with its date (the folder's or report's date) and what changed since: newer entries and changes to the files the answer draws on (`git -C <root> log --since=<date> --oneline -- entries/ direction.md stories.md profile.md`), and a different target or company. Recommend one of three, and let the user pick before drafting: **reuse** it as is (it still goes through step 7 and the review), **adapt** it (step 6 edits it), or **rewrite** it from the row's material.

Done when every free-text question has its row and scope (a new row confirmed by the user) and a starting point: a candidate from path 1 or 2 the user chose to reuse, adapt or rewrite, or path 3's material.
